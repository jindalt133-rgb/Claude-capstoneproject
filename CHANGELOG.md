# Changelog

All notable changes to this project are documented in this file.

## [0.1.0] — Initial release

Built via a full Agentic SDLC (Requirements → Architecture → Design Review →
Implementation Planning → Implementation → Code Review → Verification →
Pull Request). See `docs/` for every stage's artifact.

### Added
- `docsync` CLI (`docsync` console script and `python -m docsync`) that scans
  a Python source directory, extracts module/class/function structure and
  docstrings via static AST analysis (no code execution), and generates a
  single Markdown documentation file (FR-001–FR-008).
- Change detection so the generated file is only rewritten when extracted
  content actually changed (FR-010, FR-011).
- Sensitive-value redaction for common secret-like names (passwords, API
  keys, tokens, credentials, private-key blocks), including compound
  identifiers such as `db_password` (FR-015, NFR-003).
- Output-path boundary enforcement: all generated output is confined to
  `docs/generated/`, rejecting absolute paths, traversal, drive-relative and
  UNC forms, and symlink-based escapes (FR-016).
- Ownership-marker guard: `docsync` refuses to overwrite a pre-existing file
  at the output path unless that file was itself previously generated by the
  tool (FR-009).
- Per-file error isolation: an invalid/unreadable source file is reported
  and skipped without aborting documentation generation for the rest of the
  source tree (FR-013, FR-014).
- Default and custom exclusion patterns for scanning (`.git`, `.venv`,
  `venv`, `__pycache__`, `build`, `dist`, `node_modules` by default, plus
  user-supplied `--exclude` globs) (FR-004, FR-005).
- Full SDLC documentation set under `docs/`: `requirements.md`,
  `architecture.md`, `design-review.md`, `impl-plan.md`, `code-review.md`,
  `verification-report.md`, and ADRs under `docs/adr/`.
- Automated test suite (113 tests: unit + integration) covering the primary
  workflow, update/no-op behavior, failure isolation, sensitive-value
  redaction, and output-path security (NFR-005).

### Known limitations
- Verified and exercised on Windows only; cross-platform (Linux/macOS)
  execution has not been directly performed (NFR-001, AC-013 — see
  `docs/verification-report.md`).
- Symlink-escape and symlinked-source-file test scenarios are skipped in
  environments (including this one) where symlink creation is not
  permitted; the underlying boundary-check logic is otherwise covered by
  non-symlink negative-path tests (see `docs/verification-report.md` §9).
- No CI/CD pipeline is included; this is out of approved v1 scope
  (`docs/requirements.md`).
