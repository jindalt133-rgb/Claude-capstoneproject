## 10. Known Limitations (carried forward, not new)

1. **Windows-only execution.** All automated and manual verification in this project's history, including this Verification pass, has run on a single Windows 11 machine. NFR-001/AC-013 rely on code-level cross-platform design evidence, not multi-OS execution evidence.
2. **Symlink-dependent tests require elevated privilege on Windows** and have never executed (only skipped) in any session on this machine.
3. **NFR-002 has no numeric target** — by explicit, human-approved requirements-phase decision (`docs/requirements.md` §11), not an implementation gap.
4. **NFR-004 is a design-time claim** — no actual Git-hook/CI wrapper was built in v1 (correctly out of scope per `docs/requirements.md` §2), so "does not preclude" is verified by inspection of `core.run`'s API shape, not by building and running such a wrapper.
5. **SEC-03 (informational, from Code Review)** — a theoretical TOCTOU window between output-path resolution and the writer's existence check remains, accepted under the documented single-user/non-concurrent assumption (`docs/requirements.md` §8). Not re-litigated here; carried forward as ACCEPTED per the Code Review Remediation record.
6. **CLI stdout message nuance** observed live in Section 4 Run 4: a write-refusal (ownership-marker guard) currently produces the same stdout summary line ("no changes detected...") as a genuine no-op skip, differing only in the (correct) stderr diagnostic. This does not violate any stated FR (none specifies exact stdout wording for this branch) and is noted for completeness, not as a blocking finding.
